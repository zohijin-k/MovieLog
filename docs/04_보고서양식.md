증거 파일은 모두 `docs/evidence/Test/` 폴더에 있습니다. `results.md`는 curl로 보낸 요청의 실제 HTTP 상태, JSON code, 응답 헤더를 요청마다 한 줄씩 기록한 표입니다.

**WWW-Authenticate 확인.** 보호 API가 401을 반환한 모든 경우에 `www-authenticate: Bearer` 헤더가 포함되었습니다. TOKEN_REQUIRED(`T04.png`, `results.md` T11·T17), INVALID_TOKEN(`T09.png`), TOKEN_EXPIRED(`results.md` T10)가 모두 해당합니다. 로그인 실패(401 INVALID_CREDENTIALS)에도 같은 헤더가 포함되었습니다(`T03.png`).

**401과 403의 화면 차이.** 프론트의 `frontend/src/api.js`의 `request()`는 응답이 401이면 `clearSession()`으로 메모리의 토큰과 사용자 정보를 지웁니다. 그 결과 화면 상단이 "로그인하지 않은 상태 · 리뷰 읽기만 가능"으로 바뀌고, code에 맞는 안내가 표시됩니다. 만료 토큰(T10)에서는 "로그인 시간이 만료되어 로그아웃되었습니다. 다시 로그인하세요."가 표시되었습니다(`T10.png`). 토큰 없이 요청한 경우(T11)에는 "로그인이 필요합니다. 로그인 후 다시 시도하세요."가 표시되었습니다(`T11.png`). 403은 세션을 지우지 않으므로 로그인 상태가 유지되고, "권한이 없습니다. 본인이 작성한 리뷰만 수정·삭제할 수 있습니다."가 표시됩니다(`frontend/src/main.jsx`의 `describe()`). 화면에서는 `canEdit()`가 다른 사람의 글에 수정·삭제 버튼을 표시하지 않습니다. 그래서 403은 Bob의 토큰으로 서버에 직접 요청해 확인했고(T07·T08), 403일 때의 화면 문구는 위 코드 분기를 근거로 기술했습니다.

**실패 후 데이터 불변 확인.** 실패한 요청마다 공개 조회로 글을 다시 확인했습니다.
- Bob의 수정·삭제가 403으로 거부된 뒤(T07·T08), `GET /api/posts/11`은 제목 'Alice original', authorId 1, `updatedAt 2026-10-19T05:51:35.946765+00:00`으로 작성 시점과 같았습니다.
- 변조 토큰 요청(T09), 입력 오류(T13), 만료 토큰 요청(T10) 뒤에도 같은 값이 유지되었습니다.
- T10의 만료 토큰 수정·삭제 대상인 17번 글도 `updatedAt`이 바뀌지 않았습니다.
- 목록에는 'bad'(T09), 'forged'(T12), 'expired'(T10) 글이 생성되지 않았습니다.

**여러 오류가 겹친 경우의 실제 결과.** (`results.md` 겹침 행)
- 토큰 없이 `PUT /api/posts/999999` → 401 / TOKEN_REQUIRED
- Alice 정상 토큰으로 같은 요청 → 404 / NOT_FOUND
- Bob이 Alice 글(11번)에 공백 제목으로 수정 → 403 / FORBIDDEN
- Alice가 자기 글(11번)에 같은 입력 → 400 / BAD_INPUT
- Bob의 만료 토큰으로 같은 요청 → 401 / TOKEN_EXPIRED

명세의 처리 순서인 인증 → 글 존재 → 작성자 권한 → 입력 검증대로 응답했습니다.

**증거 1: 로그인 성공과 토큰이 첨부된 요청.** `T02.png`(로그인 200 응답, 토큰은 가림), `T02_screen.png`(로그인 후 "안녕하세요, Alice님"과 토큰 유효 시간 표시). 자동화 브라우저 로그 `browser_T02_T11_T16.txt`에는 로그인 후 `GET /api/me` 요청에 `Authorization: Bearer <TOKEN>`이 첨부되어 200이 반환된 것이 기록되어 있습니다. 로그아웃 후 같은 요청에서는 헤더가 빠지고 401 TOKEN_REQUIRED가 반환되었습니다.

**증거 2: Bob이 Alice의 글 수정·삭제를 시도한 서버 응답.** `T07.png`(`PUT /api/posts/11` → 403 FORBIDDEN, "본인이 작성한 글만 수정·삭제할 수 있습니다."), `T08.png`(`DELETE /api/posts/11` → 403 FORBIDDEN). 재조회 결과는 `results.md`의 T07·T08 행에 있습니다.

**증거 3: 토큰 변조·만료 시 서버 응답과 화면 처리.** `T09.png`(서명 변조 후 4개 요청 모두 401 INVALID_TOKEN), `results.md` T10 행(TTL 3초 토큰의 4개 요청 모두 401 TOKEN_EXPIRED), `T10.png`(만료 후 글 작성 시 로그아웃 처리와 만료 안내 화면, 서버 로그 401).

**자동 검사.** `backend/.venv/Scripts/python.exe tools/check_claims.py`를 2026-10-19 16:10에 TOKEN_TTL=90 서버에서 실행해 18/18 PASS를 확인했습니다(`check_claims_1019.txt`). 이 스크립트는 로컬 `.env`의 실습 키로 **서명은 올바르지만 클레임이 잘못된 토큰**을 직접 만들어 보냅니다. 따라서 payload만 바꿔 서명이 깨지는 경우와 구분해, 알고리즘·iss·aud·exp·sub 검사가 각각 동작함을 확인합니다. T01~T17의 수동 테스트를 대체하지 않는 보조 증거입니다. 브라우저 확인(T02 화면, T11, T16)은 Edge 자동화(puppeteer)로 실제 4173 프론트를 조작해 캡처했습니다.
